# Read exported HTML into the course model

Trace accepts a directory of static HTML pages as well as Studio inspect JSON. Studio exports supply lesson pages and block IDs in their markup. The slide layout writes one file per lesson, with deck data giving course order and authored narration; the page layout writes one file per page, whose config names its lesson, position, authored blocks and page narration. Both inputs attribute page narration to the page's first block. The reader skips redirect stubs and maps blocks into the existing `Course` shape. It removes export-only tooltip fallbacks, footnote markers and lists, and screen-reader text from on-screen word counts. Source `blockBreak` markers have no rendered element and are omitted: views chart no content from them, though later bundle refs can have different positions from inspect refs. Exported page labels can also differ from source page titles. For other HTML, the reader uses a SCORM manifest when present, otherwise index links and filenames, and extracts visible semantic content on a best-effort basis. A lesson hash covers its HTML file bytes. The reader accepts unzipped directories; it does not execute JavaScript, open zip files or recover scripted player content. When no readable content exists, it reports that limit instead of drawing an empty course.

Local readable VTT caption and subtitle tracks supply transcript prose in ordinary HTML and Studio exports. Cue identifiers, metadata and timestamps stay out of that prose. Missing tracks add no text; unexpected file errors fail the read. Captions remain anchored to the owning media block and contribute no narration or playback duration. The lesson fingerprint includes extracted caption prose so changed reviewer evidence invalidates saved answers.
