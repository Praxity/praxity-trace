# Report fields

Reference for reading `report.json` and `report.html`. Steps live in [the skill](../SKILL.md).

## Views and input coverage

Structure contains Anatomy and Pace. Objective groups belong to the Course trace view, which view links call `trace`; its Table mode lists all members, where each objective is stated and what it builds toward.

Schema 1's text projection is partial. Earlier schema 1 output has no correctness or scoring; projection 2 supplies authored correctness and scoring separately. Narration times are script estimates; stored sidecar endpoints don't establish full-file duration. Studio refs are snapshot addresses, so find content through Trace source pointers and the lesson line ranges. Schema 0, from older Studio builds' plain `praxity inspect <course-dir>`, is still accepted.

## Objective levels

`alignment.objectives[]` carries `bloomCandidates` (every listed level of the leading verb), `verbBloom` (the listed level when there is exactly one, otherwise null) and `modelBloom` (the reviewer's level from the verb and its object, or null). `bloomDiffers` is true only when a single listed level and a non-null reviewer level differ; `levelReason` records why. Each objective's `ref` resolves to its source pointer in `alignment.places`.

`bloom` keeps the single listed level as the measurement. For multi-level or unlisted verbs it uses `modelBloom`, marked generated by `bloomSource`. Read a difference as a prompt to inspect the objective's object and the reviewer's reasoning, not as a score.

## Transcripts

Transcript lines are supplied media prose, including descriptions with no speech. Projection 2 supplies authored `media.transcript`; caption-track contents stay unavailable. Schema 0 and embedded Studio HTML may supply `data.transcript`, and HTML input also reads local VTT caption and subtitle tracks. Transcripts add no on-screen words, narration time or playback time.

`language.lessons[].channels.transcript` holds transcript sentence and word summaries, and English vocabulary counts include `language.vocabulary.lessons[].transcript`. Both are absent only when the course has no transcript text. Transcript sentences use `channel: "transcript"` and ids such as `3.9.t2`, with the owning media block's ref.

Terms flags, Tasks evidence and Visuals opportunities accept `screen`, `narration` or `transcript`, and each quote must occur in its cited channel. Alignment support also accepts `tooltip`. `availability.checks[].available` can be `transcript`, labelled "In a transcript only".

## Item cues

Only single-selection choices with exactly one known key and at least two readable text options are included, even when unscored. Read `excluded` and `excludedCount`; each reason names the field, tag, attribute or bracket to fix or check by hand. Trace excludes an item when:

- its HTML uses markup beyond attribute-free `p`, `strong`, `em`, `code`, `del` and `mark`; `a` with only `href`; tooltips with exactly `class="inline-tooltip-trigger"` and `data-tooltip-content`; and doodles with exactly `class="praxity-doodle"`, `data-doodle` and `data-doodle-mods`;
- an icon or variable placeholder hides what the learner sees;
- its question or options still contain square or curly brackets once glossary definitions are removed, even brackets meant as text.

Tooltip definitions stay out of solver inputs. Shuffled and shuffle-unknown items keep authored positions as evidence but are left out of fixed-position counts.

Each item has a visible `label` with its full block ref and a short stem excerpt, used in all three probe result arrays. HTML rows add the source file and line.

Item-cues uses prompt version `item-cues/9-projection-2`. Preparation creates the solver bundle and a sibling review folder, `<bundle>-review/`. Its `operator.json` alone records `seed` and `optionOrder`, mapping refs to zero-based source indices; solver choices remain one-based. Keep keyed `course.json` in a private input folder outside the bundle's parent tree. Give each solver only its probe folder copied into a separate workspace, or supply the files inline; keep the operator workspace out of reach. The bundle manifest carries `view`, `promptVersion`, `courseHash`, `bundleId` and masked applicability, without seed or order. Each preparation gets a new random 128-bit `bundleId`, independent of the seed; the operator file stores their association. Reusing a seed replays content and option order, not the ID. Each probe's items carry `bundleId` and a `probe` tag. Echo those unchanged at the top of each solver answer. Tags are `masked`, `choices-only` and `cover-the-options`. Combine these objects under `masked`, `choicesOnly` and `coverTheOptions` in `<review>/answer.json`. Report reads `operator.json` beside the answer. Moving the combined answer requires moving its operator file too.

Applicable masked and plain answer objects have `{bundleId, probe, model, answers}`. Each row has `ref`, one-based `choice`, a supported `cue` code from the prompt and `note`; `other` needs an explanation. Cover-the-options uses the same identity fields, with `ref` and short free `answer` rows. Every applicable solver answers every supplied item once. An unavailable masked probe instead echoes `{bundleId, probe: "masked", applies: false, reason, detail}`.

A scored `masked` has `applies: true`, `model`, `right`, `total`, `chanceExpected`, `p`, `pLow`, `tooFewItems`, `tooFewItemsLow`, `cueCounts` and `items`. The gate fields are `itemCues.course.masked.p` and `itemCues.course.masked.pLow`; banks have the same shape. Both tails include the observed count and each item's `1/options`, using the exact Poisson-binomial for mixed option counts. `choicesOnly` keeps the same score fields as the "does the stem matter?" diagnostic, because subject knowledge may identify the only generally true option. Small-bank flags mean that tail cannot establish evidence, never a pass. Avoid interpreting isolated banks or repeated runs as independent evidence.

Masked applicability is `{applies: false, reason: "language", detail}` when course metadata is not nominally English, an included lesson's supplied `lang` is not English, or the text screen fails. Inspect may default `course.locale` to `en`; that value alone cannot confirm language. Across included stems, at least 20% of word tokens must be in the English keep list; every stem of four or more words needs at least one keep word. Failures include measured share, counts and threshold in `detail`. The floor was calibrated on five English fixtures at 43.3-65.0% and synthetic French/Spanish fixtures at 0%. This is a limited screen, not language identification. It is `{applies: false, reason: "mask-space", detail}` if any item has no unused masking form left or any content word still contains a combining mark after NFC. Neither has scores or tail probabilities. Nothing passes from an unavailable probe.

Masking normalizes text to NFC, then uses one deterministic injective dictionary across each item's stem and options. Content words become same-length pseudo-words, preserving article-sound class with a small common-exception table and a shared base plus trailing `s` for regular singular/plural forms. Silent-h hour, honest, honour/honor and heir families take a vowel onset; uni-, use, usu-, ur-, eu-, one and once take a consonant onset. All-caps initialisms use first-letter names: A E F H I L M N O R S X take an. This covers common exceptions and spelled initialisms only. Singular -us, -is and -ss endings remain whole; other irregular inflections stay separate. English function words, hedges, absolutes, consultation words and punctuation remain. Digits use one consistent scrambled map per item. Replacements never reuse another word's output, equal a kept word or equal a source word. Report item rows show authored stems, responses and keys. `items[].masked` holds `{stem, response, key}`, shown in expandable HTML details.

`coverTheOptions` keeps every stem, response and key with its judgement or null. Before judgement, `right` is null and `status` is "not judged". Matches and `alsoCorrect` answers both count in `right`, the number of defensible stem answers; `outcomes.alsoCorrect` counts the other valid answers separately. There is no p value for free answers, and answerability is a different question from choices-only cue detection.

`cueCounts` reports cues to the key. `writingCounts` reports high option overlap and shared openings, which may be intentional parallel options. Each pattern has an author action with limits against overcorrection. `masked.cueCounts` and `choicesOnly.cueCounts` total solver cue codes.

Convergence is a bank or course statistic against guessing, including exact fractional tie-credit tails. Only a unique key maximum is listed per item, and it is left out of `cueCounts`. Consultation is also a bank share, never an item flag. English lexical rules run only for an `en` locale; other languages show "Not checked: English-only rule" in `applicability`. Unicode duplicate, overlap and shared-lead checks always run. Duplicate detection preserves signs, meaningful symbols, fractions and decimal separators.

`spreads` separates option counts and gives authored positions, known fixed-order positions, shuffled and unknown counts, length ranks and longest-key counts including ties. Length is the visible character count including spaces; rank 1 is shortest and ties share the lower rank. The equal-share reference is items divided by options. The 10 to 40% rank band needs at least 20 items; use the pooled course spread for smaller banks. Spread key length ranks across the bank rather than moving every key to another single rank.
